# 0014. setup-docs 진단-주도 제안 모델 (경직 게이트 대신 유연 지시문)

- 상태: 수락
- 날짜: 2026-07-07

## 맥락

setup-docs를 실제 target(jio.dev — 자체 문서구조·라우터를 갖췄으나 인덱스가 평문 화살표라
`gate` FAIL, orphan=50)에 e2e로 돌려 세 실패를 관측했다. 오염 없는 fresh 에이전트로 **현재
스킬**을 재실행한 베이스라인에서도 동일 재현 — **스킬 결함이지 실행자 실수가 아님**:

1. **결정 회피/오제시:** MESSY가 곧장 "전면 재배치 파이프라인"으로 직행. migrate냐 보강이냐의
   선택을 사용자에게 주지 않고, 잘 정리된 트리에 worktree+content_oracle 무거운 경로를 단일 제안.
2. **거친 MESSY 버킷:** "파일 이동 필요한 재배치"와 "링크 포맷·인덱스만 깨진 경량"이 한 버킷.
   jio.dev는 **파일 이동 0**으로 도달성 복구가 가능(인덱스 파일 추가 + 링크 포맷 교정)한데도
   전면 재배치로 판정됐다.
3. **성장 루프 opt-in→스킵 유도:** 루프를 "설치할까요/스킵" opt-in으로 제시([0007](0007-hook-trust-model.md)·
   DESIGN §7). 가치가 명백한데도 미설치로 기욺.

뿌리: SKILL.md가 "절차"는 주되 **"무엇을 권장하고 어떻게 제시하는가"를 비워**, 에이전트의 일반적
보수 휴리스틱이 진공을 메움. 상태 분류도 너무 거칢. (map 중추는 이미 자동 — "무조건 spine"은
현행에서 성립.)

## 결정

**진단-주도 제안 모델.** 진단이 자세를 정하고, 에이전트는 사용자에게 *제안*한다. 이를 결정론
게이트/시스템이 아니라 **SKILL.md 산문 지시문**으로 준다 — 케이스가 열려 있어 경직된 제약은
오히려 AI의 유연한 판단을 막는다.

| 진단 | 자세 |
|---|---|
| **GREENFIELD** | 조용히 설치, 질문 없음 |
| **MESSY·중구난방**(보강조차 어려운 혼돈) | 선택지 **안 줌** — "마이그레이션 불가피" 이유 고지 + 승인만, migrate 적극 권장 |
| **MESSY·자체구조**(합리적이나 우리와 다름) | migrate vs 보강 **선택지 제시** + 트레이드오프 쉬운 설명 + **migrate 권장** |
| **HEALTHY**(이미 docsherpa) | 우리 아키텍처 기준 개선점 리뷰, 무변경 |

- **map 중추(spine)·성장 루프 = 무조건**(질문·스킵 대상 아님). 루프는 "설치 vs 스킵" 선택지가
  아니다. **단 [0007](0007-hook-trust-model.md) 트러스트는 유지** — 무엇을 쓸지 diff-preview +
  harness 훅-승인 게이트. **"필수 기능"과 "보안 투명성"은 별개 축**이다. (§7의 opt-in을 "설치
  여부 선택"이 아니라 "쓸 것 고지·승인"으로 재해석; loop 스킵 옵션 제거.)
- **보강(reinforce):** 기존 폴더를 그대로 두는 게 아니라 **크게 벗어나지 않는 선에서 최소공수
  재조정** + 트레이드오프 명시 + migrate로 유도.
- **MESSY 2차선:** 파일 이동 불필요(링크 포맷·인덱스만) → **경량 차선**(worktree·content_oracle
  없이 링크 교정 + 인덱스 체인/README 신설 + `gate`). 이동 필요 → 기존 무거운 재배치 파이프라인.
  판정 룰: *"옮겨야 할 문서가 있나? 없으면 경량."*
- **경량 차선용 진단 신호(knowledge.md 안티패턴 추가):** 라우터/인덱스가 평문 화살표·백틱 경로
  (비-markdown 링크)라 `gate` 미인식 → 트리는 멀쩡해도 orphan.

## 결과

- 좋음: 정본 결정(map·루프)을 위임 안 함 · 상태에 맞는 제안 · 잘 정리된 트리에 경량 대응 ·
  중구난방엔 migrate 강권.
- 대가: 행동이 유연해 **결정론 채점 불가** → 수용 기준(루브릭)을 2계층으로 — **행동은 판정자가
  "진단-적절성"으로**(키워드 매칭 아님, 명백한 미스매치만 FAIL) + **기계는 `gate`·`content_oracle`.**

  **수용 기준 (setup-docs 1회 실행 채점 — jio.dev = 자세3 fixture):**

  | # | 항목 | 유형 |
  |---|---|---|
  | B1 | 진단이 맞았나 (jio.dev=자세3) | 판정 |
  | B2 | 자세 부합 제안: 선택지 + 트레이드오프 쉬운 설명 + migrate 권장 | 판정 |
  | B3 | spine·성장루프를 **안 묻고** 자동 (물으면 FAIL) | 판정 |
  | B4 | 경량 접근 — 불필요한 worktree/이동/무거운 파이프라인 안 씀 | 판정 |
  | M1 | `gate` broken=0·orphan=0 | 기계 |
  | M2 | 마커 계약(`--require-markers`) | 기계 |
  | M3 | 무손실 `content_oracle` PASS (에이전트 매니페스트 + base 스냅샷) | 기계 |
  | M4 | 2회차 재실행 변경 0 + fresh 재실행이 HEALTHY(자세4) 진단 | 기계 |

  하네스: 중립 프롬프트→제안 채점(B) → "권장대로"→실행 채점(M) → fresh 재실행→M4.
  합격 = 적용 항목 전부 PASS. 베이스라인(현 스킬)은 B2·B4 FAIL·루프 opt-in로, 루브릭이
  실패를 잡음을 실증.

- 근거등급 🟡(판단). 외부 권위 아님 — 근거정직성 철칙대로 표시.
- [0007](0007-hook-trust-model.md)·§7과 화해: 루프는 기능상 필수지만 훅-쓰기 트러스트 세리머니는
  보존. §7 "opt-in" 프레이밍은 이 ADR로 정정(스킵 선택 제거, 고지·승인은 유지).
- 거부한 대안: 결정론 게이트로 자세 강제(유연 판단 죽임) · 루프 opt-in 유지(가치 명백한데 스킵
  유도) · MESSY 단일 무거운 파이프라인 유지(경량 케이스 과잉대응).
