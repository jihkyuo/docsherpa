# 진단-주도 전체-repo 마이그레이션 (setup-docs 재설계) — design

- 상태: 제안 (브레인스토밍 완료, 리뷰 대기)
- 날짜: 2026-07-07
- 선행: [ADR 0014 진단-주도 제안](../../decisions/0014-setup-docs-diagnosis-driven-proposal.md) · [하드닝 루프](../../plans/2026-07-07-setup-docs-hardening-loop.md)
- 파생 ADR(구현 시 신설): 모듈 분해(`doc-health` 추출) · 마이그레이션 미션(전체-repo 중앙집중) · 아티팩트 렌더러(동결 템플릿)

## 1. 배경 · 문제

하드닝 루프 Round 3(vd-front 독푸딩)에서 setup-docs 진단이 다음 4개 간극을 드러냈다.

- **G1 — 탐색이 `docs/` 중심.** Phase 0는 `docs/` 트리와 진입 라우터만 스캔한다. 프로젝트 전반 문서(루트 산재·숨은 폴더·코드옆 `src/**/docs/`)를 **모두** 찾는 의무·병렬 서브에이전트가 없다.
- **G2 — `docs/` 밖 문서 방치.** gate 도달성은 `docs/**`만 본다(`gate.py:115`). 밖 문서는 고아로도 안 잡히고 계획에도 안 들어가, 경량 차선이 "옮길 것 없음→끝"으로 너무 쉽게 방치한다. → 유실.
- **G3 — 전-계정팅 계획 부재.** 무거운 차선은 "옮길 것"만 계획한다. 발견된 전 인벤토리에 처분을 부여해 하나도 잊지 않는 단계가 없다.
- **G4 — 설치 ≠ 완료.** 비어있지 않은 `docs/`에 `scaffold()`를 돌리면 기존 고아를 방치하고 "성공"으로 착각한다(`_MAP_DOC`가 decisions/how-to만 링크).

핵심 진단: setup-docs의 심장(탐색 → 전-계정팅 계획 → 유실 0)이 **`docs/` 중심 + 방치 기본값**이라 실제로 강제되지 않는다.

## 2. 미션 (재정의)

setup-docs는 아키텍처를 "슥 설치하고 끝"이 아니다. **프로젝트 전반의 모든 문서를 발견하고, `docs/` 아래 우리 아키텍처로 마이그레이션하며, 그 과정에서 문서 유실을 0으로 만든다.** `docs/`가 모든 문서의 단일 홈이 된다.

- **불가침:** 유실 0(loss = 잊히거나 내용이 사라진 문서). docsherpa North Star와 정합.
- **중앙집중:** 모든 문서를 `docs/`로 물리 이동. **예외 없음** — 외부 툴이 고정 경로로 추적하거나 코드가 참조하는 문서도 이동하고, 깨지는 참조는 **임팩트 플래그**로 사용자에게 고지(고치는 건 사용자 몫).
- **정직:** 완결을 과선언하지 않는다. 결과는 실제 달성 등급으로 보여준다.

| D2 | 전체-repo 병렬 탐색(기계 파일목록 + 에이전트 분류) | G1·G2. 완결성 = 파일목록이 분모 |

## 4. 모듈 분해

정합성·재사용을 위해 진단을 별도 모듈로 뺀다.

| 모듈 | 성격 | 책임 |
|---|---|---|
| **`doc-health`** (신설 스킬) | 읽기 전용 | 전체-repo 탐색 → 9차원 점수표 → 등급 → 자세. `{인벤토리, 점수표, 등급, 자세}` 데이터 반환. 독립 호출 가능(수시 건강검진) |
| **`setup-docs`** (리팩터) | 변경 | `doc-health` 호출(Phase 0·4) + 목표트리·계획 + worktree 실행(oracles) |
| **`render_report.py`** (공유 스크립트 — **스킬 아님**, `gate.py`류) | 결정론 함수 | 진단/계획 데이터 → 자기완결 HTML 아티팩트. Phase 2·4가 공유 |

**정합성 논거(단순 DRY 아님):** Phase 0(before)와 Phase 4(after) 등급은 **반드시 동일 채점기**로 재야 "F→A" 비교가 참이다. 공유 모듈이 이를 구조적으로 보장한다.

**경계:** 진단 = 읽기전용(데이터 생산). setup-docs = 소비 + 변경. 깨끗이 분리.

## 5. 파이프라인 (6단계)

```
0a 병렬 탐색(완결)   → 0b 채점(등급)      → 0c 자세 판정      [doc-health]
1a 목표트리(그룹핑)  → 1b 자체검증(A 증명)                    [setup-docs]
2  계획 아티팩트     → 사용자 승인 + 결정 2건                 [render_report]
3  worktree 배치 실행(두 오라클·유실0)                        [setup-docs]
4  결과 아티팩트(실제 재진단·정직한 달성등급) → 확인 → 랜드   [doc-health + render_report]
```

자세별 차등: GREENFIELD=조용히 설치(아티팩트 없음). HEALTHY=등급 카드만. MESSY=풀 파이프라인.

> **구현 spec:** [setup-pipeline.md](setup-pipeline.md) — 증분 3(Phase 0·1·2: 진단→목표트리→검증된 계획→승인).
> [landing-migration.md](landing-migration.md) — 증분 4(Phase 3·4: 승인된 계획의 실제 랜딩→재진단, worktree 격리·D1 도달성-구동 등록·D2 new-vs-preexisting 링크).

## 6. 진단 상세 (`doc-health`)

> **구현 spec(증분 2):** [doc-health.md](doc-health.md) — 이 절을 구현-준비 상세로 구체화(스킬 골격·탐색 스크립트·채점 산식·데이터 계약·사용자 합의 결정 H1~H3).

### 6a. 탐색 — 2단계 (기계 인벤토리 → 병렬 분류)

"방구석까지 다 찾기"는 단일 에이전트가 훑으면 빠뜨린다. **분모는 기계가, 분류는 병렬 에이전트가.**

1. **기계 파일 인벤토리(결정론):** repo 전체 `*.md`·`*.mdx` 나열, 제외 `node_modules`·`.git`·`dist`·`build`·`vendor`. → 모든 문서의 확정 목록(= "잊힌 문서 0"의 분모). 스크립트로 수행.
2. **병렬 서브에이전트 분류(멀티모달):** 목록을 슬라이스로 나눠 동시에 각 문서 판정 → `{경로, 타입추정(ADR/spec/how-to/reference/PRD/legacy), 역할, 결합(코드참조·외부싱크·동결역사), 요약}`.

**완결성 가드:** 분류 매니페스트는 1단계 목록을 **전부** 덮어야 함(unaccounted=0). 파일이 목록에 있는데 매니페스트에 없으면 STOP. 구조적으로 못 빠뜨림.

### 6b. 채점 — 9차원 점수표 → 등급

| | 차원 | 채점 | 주체 |
|---|---|---|---|
| M1 | 도달성 (broken=0·orphan=0) | ✅/❌ | gate |
| M2 | 진입 라우터 + 마커 계약(home 정확히 1) | ✅/❌ | gate --require-markers |
| M3 | 맵 척추(`docs/_map.md` 인덱스·라우팅) | ✅/❌ | gate |
| M4 | 성장 루프 3종(prime·doc-reconcile·훅) | ✅/❌ | ls |
| M5 | 전체 커버리지(`docs/` 밖 문서=0) | ✅/⚠️/❌ | 탐색 스윕 |
| J1 | 문서타입 분류 정확성 | ✅/⚠️/❌ | 판단(knowledge.md) |
| J2 | 폴더승격 적정성(co-change·over/under 없음) | ✅/⚠️/❌ | 판단 |
| J3 | hollow·중복·bloat 없음 | ✅/⚠️/❌ | 판단 |
| J4 | 정합성 플래그(중복·모순 감지·보고) | ✅/⚠️/❌ | 판단 |

**하이브리드:** M1~M4 = gate 결정론(scorecard JSON). M5 = 탐색 카운트. J1~J4 = 서브에이전트 판단. 등급 롤업 = scorecard 위 결정론 함수.

**등급 산식(게이트형 — 도달성이 관문):**
```
A  전 차원 ✅                          ← 마이그레이션 목표
B  M1~M5 전부 ✅, J 중 ⚠️ 1~2개
C  M1 ✅ 이나 M2~M5 중 1~2개 ❌/⚠️
D  M1 부분(다수 고아) 또는 M5 대량 밖
F  라우터 없음 / 대부분 미도달 / 중구난방
```
각 비-✅ 차원 = 마이그레이션 계획의 to-do 한 줄. **최고 등급 A = 전 차원 ✅ = 완료 정의.**

**루브릭 이중성:** 이 doc-health 루브릭(타겟 채점)은 하드닝 루프 자가-평가 루브릭(ADR 0014, setup-docs *행동* 채점)과 형제지만 대상이 다르다(전자=repo, 후자=스킬).

### 6c. 자세

GREENFIELD / HEALTHY / MESSY(중구난방·자체구조·드리프트된-docsherpa) — ADR 0014 계승. 미션 변경으로 MESSY·자체구조의 기본이 "방치"에서 "전-계정팅 마이그레이션"으로 강화됨.

## 7. 목표 트리 설계 (`setup-docs` Phase 1a)

인벤토리 → 각 문서에 `docs/` 내 목적지 배정.

- **타입 먼저:** `decisions/`·`how-to/`·`specs/`·`product/`·`reference/`.
- **토픽 폴더는 co-change일 때만:** 서로 같이 읽어야 할 문서 ≥2개일 때 `docs/<topic>/` 승격.
- **금지:** 1문서1폴더(over-folder)·60개 평면덤프(under-index) 양극단. 폴더>3개면 `_README` 계층화.
- **정규화(D8):** 위치·이름만 정규화(순수 이동/개명, 유실0). 내부 포맷 재구성은 **opt-in** — 선택 시 content_oracle `transformed`로 세그먼트 계정팅 + 아티팩트에 표시. 미선택 시 verbatim, 이후 성장 루프가 내용 관리.
- **동결 역사:** 날짜박힌 `specs/`·`plans/`는 인덱스만(내용 verbatim, repoint·삭제 금지).

**1b 자체검증:** 목표 트리를 임시 빌드 → gate + content_oracle 통과 + 등급=A 증명. **여기까지 된 뒤에** 아티팩트로 사용자에게 제시.

## 8. 마이그레이션 실행 (`setup-docs` Phase 3)

> **실행 상세는 [landing-migration.md](landing-migration.md)(증분 4)가 정본** — 아래는 개요. 특히 실행 단위·오라클은
> 증분 4에서 **단일 원자 적용**(배치 아님, L2)·**세 판정 + 앵커/인스턴스**로 정련됨.

- **격리:** 전용 worktree(current)+새 브랜치 & 두번째 worktree(base@핀HEAD). 타겟 작업트리·WIP 무해(비-git이면 STOP).
- **실행 단위:** 검증된 전체 계획을 **한 번에 원자 적용**(chained-move·전역 relink는 함께 처리 — 배치로 쪼개면 깨짐). 검증한 트리를 그대로 커밋.
- **오라클(유실0 핵심):**
  - 도달성(`gate.py`): orphan=0 + **new_broken=0**(마이그레이션 자가유발 링크 파손 0, 기존 broken은 보존·표면화) + 앵커 보존
  - 내용보존(`content_oracle.py`): unaccounted=0 + **per-file 목적지 회계**(문서-인스턴스 소실 차단)
- **STOP 조건:** content_oracle unaccounted · gate 2회 픽스 후에도 0 실패 · 목적지 충돌 · 승인 계획 밖 발견.
- **마무리:** 척추·성장루프 설치 → 최종 `gate --require-markers` → Phase 4 재진단.

## 9. 아티팩트 — 동결 렌더러 (`render_report`)

**문제:** 에이전트가 매 실행 HTML을 자유생성하면 품질이 흔들린다(대비 깨짐·slop·cascade 버그).

**해법:** 셸(CSS·토큰·테마·컴포넌트·대비·레이아웃)과 데이터를 분리. 셸은 **한 번 저작·검증 후 동결**, 데이터만 주입.

- **저작 원본:** `~/Downloads/docsherpa-phase2-diagnosis-mockup.html`(이 세션에서 hand-tune + WCAG 실측 + codex 교차검증한 v5). 내용을 빼 템플릿화한다.
- **렌더러:** 데이터 모델(JSON) → 자기완결 HTML. 빈칸 채움 + 반복행(문서 N개) 생성 + **HTML 이스케이프**(경로·문서명의 `<>&`).
- **품질 게이트(한 번 만들면 영구):**
  - **대비:** 토큰 쌍 WCAG AA(≥4.5 소형/≥3.0 대형) 자동 테스트. 밑돌면 CI 빨감.
  - **구조:** 인라인 style=0 · 태그 밸런스 · 외부 리소스 0(CSP 자기완결) · 시맨틱 헤딩 · 비버튼(인터랙티브 위장 금지).
  - **픽스처:** 문서 0/소수/대량·플래그 0건·이미 A등급·긴 경로·특수문자 → 레이아웃 불변.
- **모드:** `plan`(Phase 2 — 진단 + 마이그레이션 표 + 결정 패널) / `result`(Phase 4 — 진단 + 완료 요약 + 정직한 달성등급).

**표현 품질 = 동결 렌더러 보장. 진단 정확성 = gate + 루브릭 + 하드닝 루프 보장.** 두 축을 분리해 각자 잠근다.

## 10. 결정 표면화 (Phase 2 결정 패널)

자동으로 안 고치고 사용자에게 시각적으로 제시(번호 + A vs B):

- **라우터(F-B):** 리치 CLAUDE.md + AGENTS.md 없음일 때, 껍데기 AGENTS.md를 억지로 만들지 않고 두 안 제시(①CLAUDE.md를 정본 라우터 인정[추천] / ②AGENTS.md 승격). 스킬이 혼자 정하지 않는다.
- **내용 모순:** 두 문서가 충돌 값 주장 시(예: node-linker hoisted vs isolated) 병합 정본을 사용자가 선택. 자동수정 안 함(구조≠사실검증).

## 11. 유실 0 보장 (3중)

1. **탐색 완결성** — 기계 파일목록이 분모, 매니페스트가 전부 덮음(unaccounted=0).
2. **이동 안전성** — 순수 이동(내용 verbatim), content_oracle 세그먼트 계정팅.
3. **랜딩 게이트** — 검증트리=커밋트리(worktree 그 자리 검증), 오라클 전부 통과 시에만 커밋, 실패/크래시 시 흔적 0(landing-migration.md).

## 12. 산출물 (구현 시)

- **스킬:** `skills/doc-health/`(SKILL.md + reference) 신설. `skills/setup-docs/` 리팩터(진단 위임 + Phase 4 추가).
- **스크립트:** 탐색 인벤토리(파일목록), `render_report.py`(렌더러) 신설. 기존 `gate.py`·`content_oracle.py`·`scaffold.py` 재사용/확장.
- **템플릿:** 동결 아티팩트 HTML 템플릿(저작 원본에서 파생).
- **테스트:** 렌더러 대비(WCAG)·구조·이스케이프·픽스처. 탐색 완결성(unaccounted=0). 등급 산식(scorecard→등급). 배치 오라클 회귀.
- **문서:** ADR(모듈 분해·미션·렌더러). `_map.md`·AGENTS.md 라우팅 갱신. 하드닝 루프 문서에 "타겟 = doc-health" 반영.

## 13. 스코프 밖 · 이연

- **외부 doc-루프 특화(기각):** 타겟에 이미 있는 doc-freshness 툴(예: Confluence 싱크)을 특별 처리하지 않는다. merge_settings가 기존 훅을 보존할 뿐, 우리 할 일만 한다.
- **청소(이연):** 중복·낡은 문서의 삭제/dedup은 별도 논의. 유실 0 원칙상 함부로 못 지운다. 마이그레이션은 "이동·계정팅"까지, "삭제"는 아님.

## 14. 열린 질문

- 등급 A~F 경계의 정밀 임계값(하드닝 루프로 튜닝).
- 렌더러 구현 형태(순수 스크립트 vs 컴포넌트 조립) — 결정론·이스케이프 보장이 기준.
- `doc-health` 호출 기전(스킬 인보크 vs 공유 절차 참조) — 구현 시 확정.
- 비-`.md` 문서(.rst·.adoc 등) 취급 — 현재 `.md`/`.mdx` 1급, 그 외는 플래그(YAGNI).

## 15. 검증 계획 (성공 기준)

- 탐색: 합성 fixture(숨은 폴더·코드옆·루트 산재)에서 unaccounted=0.
- 채점: 알려진 상태의 fixture가 기대 등급을 산출(F/C/A).
- 렌더러: 대비 테스트 그린 + 픽스처(엣지) 레이아웃 불변 + 이스케이프.
- 마이그레이션: vd-front(또는 격리 사본)에서 배치 실행 → 두 오라클 그린 + 재진단 A + fresh-agent 변이 수렴.
- 정직: 결과 아티팩트가 실제 등급 표시(A 미달 시 잔여 항목 노출).
