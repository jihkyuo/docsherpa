# 실사용 회고 — 설치된 레포에서 루프가 정말 도는지 확인하고 개선하기

> **사용자가 기억할 것은 이 한 문장뿐이다:**
>
> ## 🔔 **"<레포명> 일주일 돌렸다. 회고 돌려."**
>
> 나머지는 전부 이 문서에 있다. 에이전트는 이 문서를 읽고 아래를 순서대로 수행한다.
> 사용자에게 절차를 되묻지 마라.

**왜 이 문서가 있나.** 세르파는 설치되고 나면 사용자 레포에서 조용히 돈다. 그 결과를 자동으로
플러그인에 보고하는 파이프는 **없고, 앞으로도 만들지 않는다**(메커니즘 과잉 생산이 이 프로젝트의
병이다 — [ADR 0019](../decisions/0019-freeze-heavy-lane-and-renderer.md)). 대신 **루프가 이미
자기 일지를 쓴다**: 커밋 메시지의 `Docs-Impact:` 트레일러. 회고는 그 일지를 읽는 일이다.

---

## 0. 언제 도는가

**코드를 건드린 커밋이 10개 이상 쌓였을 때.** 대략 일주일.

이틀 만에 돌리지 마라. 실측으로 확인했다 — n=3에서 검출률의 95% 신뢰구간이 `[0.10, 0.99]`였다.
표본이 적으면 노이즈를 패턴으로 착각하고, 존재하지 않는 문제를 고치러 간다.

## 1. 숫자 세 개를 낸다 (스크립트 만들지 말 것 — 아래 명령을 그대로 친다)

> 세 번 넘게 손으로 돌리게 되면 그때 스크립트화한다. 그 전엔 아니다.

`<repo>` = 세르파가 설치된 사용자 레포. `<code>` = 그 레포의 소스 디렉터리들.

### M-A. 일지 준수율 — 루프가 발동은 하는가 (분모)

```bash
CODE=$(git -C <repo> log --oneline --since='1 week ago' -- <code> | wc -l)
TRAIL=$(git -C <repo> log --since='1 week ago' --grep='Docs-Impact' --oneline | wc -l)
echo "$TRAIL / $CODE"
```

doc-reconcile §7은 **무변경이어도 `Docs-Impact: none`을 남기라**고 지시한다. 준수율이 낮으면
*"루프가 안 돌았는지"* 와 *"돌았는데 바꿀 게 없었는지"* 를 **구별할 수 없다** — 그게 첫 번째 갭이다.

**설치 직전에 이 값을 베이스라인으로 기록해 두라.** 오르지 않으면 루프가 안 돌거나 산문을 안 따른다.

### M-B. 노후 지연 — 앵커 쌍마다, 문서가 얼마나 뒤처졌나

앵커 쌍은 설치본 `doc-reconcile/SKILL.md`의 `docsherpa:anchors` 블록에 적혀 있다(§7.5에서 그 레포에
맞게 특화된 것). 각 쌍마다:

```bash
DT=$(git -C <repo> log -1 --format=%ct -- <문서>)
git -C <repo> log --oneline --since="@$DT" -- <코드> | wc -l   # 문서 갱신 뒤 코드가 바뀐 횟수
```

⚠️ **이 숫자는 판정이 아니라 랭킹이다.** 지연이 크다고 놓친 게 아니다 — 정말 안 고쳐도 되는 문서일
수 있다. 위에서 몇 개만 열어보면 되고, 전부 눈으로 볼 필요는 없다.

### M-C. 루프가 그 기간에 무엇을 만들고 고쳤나

```bash
git -C <repo> log --since='1 week ago' --name-status --format='%h %s' --grep='Docs-Impact'
```

## 2. 빨간불을 찾는다 (여기가 핵심)

실측이 알려줬다 — 세 축의 성질이 다르다([ADR 0022](../decisions/0022-harness-scope.md)).

| 축 | 성질 | 회고에서 |
|---|---|---|
| **탐지**(낡은 문서 찾기) | 확률적. 제대로 재려면 n≈41 | **재지 않는다.** M-B는 랭킹일 뿐 |
| **억제**(필요 없는 문서 안 만듦) | 이진·희귀사건 | **한 건이라도 나오면 빨간불** |
| **보존**(사실인 문서 안 건드림) | 이진·희귀사건 | **한 건이라도 나오면 빨간불** |

- **억제 위반:** 루프가 만든 ADR·how-to·spec 중 있으나 마나 한 것. M-C의 `A`(added) 목록을 본다.
- **보존 위반:** 여전히 사실인 문서를 헤집었다. M-C의 `M`(modified) 중 실제로 거짓이 아니었던 것.
  나중에 되돌려진 편집이 있으면 강한 신호다.

## 3. 지각 갱신을 공짜 시나리오로 바꾼다

문서가 **뒤늦게** 갱신된 커밋은 그 자체가 정답지 붙은 시험 문제다 — `Docs-Impact:` 트레일러에 판정이
산문으로 있고, 변경 파일이 정답이다. [parity 실험](run-parity-experiment.md) §2 형식으로 시나리오
JSON을 만들어 사용자 레포에 쌓는다.

**쓸수록 시험지가 늘어난다.** 플러그인 코드는 한 줄도 안 는다.

## 4. `FINDINGS.md`에 숫자를 적는다

다음 회고의 기준선이다. 숫자만. 서사는 짧게.

## 5. 세 갈래로 갈린다 — 여기서 결정한다

### 갈래 A — 빨간불(억제·보존 위반)이 켜졌다
**한 건이라도 즉시 고친다.** 희귀하고 해롭다. 고치는 곳은 `skills/doc-reconcile/SKILL.md`의 **산문 한 곳.**

### 갈래 B — 같은 실수가 **두 번 이상** 반복됐다
한 번은 우연이다(LLM은 확률적이다). 두 번이면 패턴이다. 역시 **산문 한 곳.**

### 갈래 C — 아무것도 안 나왔다
**개선하지 않는다. 출시한다.**
"고칠 게 없는데 계속 파는" 습관이 220커밋을 만들었다. 여기서 멈추는 게 이 문서의 존재 이유다.

## 6. 고칠 때의 규칙 (A·B에 해당할 때만)

1. **한 번에 산문 한 곳.** 여러 곳을 동시에 고치면 무엇이 효과였는지 모른다.
2. **쌓인 시험지를 [하네스](run-parity-experiment.md)에 돌린다.** 억제·보존이 온전한지 확인한다.
   여기가 무너지면 개선이 아니라 퇴행이다. (탐지 수치는 보지 마라 — n이 모자라 의미 없다.)
3. **버전을 올린다**(`plugin.json`). patch면 충분하다.
4. 다음 세션에 `refresh.py`가 사용자 레포의 설치본을 **자동 갱신**한다. 로컬 편집이 있으면
   `stuck`으로 멈추고 알린다(안 덮는다).

**4번이 기둥 2(버전관리 업데이트)의 실전 검증이다.** 회고를 돌 때마다 저절로 재진다 —
`refreshed`가 뜨는지, `stuck`·`noop`이 뜨는지 확인하고 기록하라.

---

## 하지 말 것

- **텔레메트리 파이프라인을 만들지 마라.** 사용자가 방아쇠다. 그게 설계다.
- **탐지 재현율을 올리려 하지 마라.** 측정 불가다(n≈41). [ADR 0022](../decisions/0022-harness-scope.md).
- **회고 자체를 스크립트로 만들지 마라.** 세 번 손으로 돌린 뒤에 다시 생각한다.
